## 设计原则

1. **20个 Q&A**，覆盖项目最常见的5类问题
2. 每类4个，均匀分布
3. 答案必须**结论先行**，2-5句话给出直接答案
4. 必须标注**关键代码位置**
5. 必须给出**置信度**（高/中/低）
6. 高价值问题提供**延伸问题**

---

## 问题分类和数量（每类4个，共20个）

| 类别 | 代码 | 问题示例 |
|------|------|---------|
| 模块与架构 | ARCH | 项目的模块是如何划分的？AuthModule 依赖哪些模块？ |
| 路由与认证 | AUTH | 哪些接口需要管理员权限？JWT Token 如何刷新？ |
| API 与业务 | API | 用户注册流程是什么？如何分页查询文章列表？ |
| 数据与查询 | DATA | 用户和文章是什么关系？如何自定义查询？ |
| 配置与部署 | DEPLOY | 项目有哪些环境变量？如何配置数据库连接？ |

## 每条Q&A的格式（必须严格遵守）

```markdown
---
**Q{序号}** [{类别}] {问题文本}

**答案**：
{直接给出答案，2-5句话，结论先行}

**关键代码位置**：
- `{文件名}:{行号}` — {一句话说明这里有什么}
- `{文件名}:{行号}` — {一句话说明这里有什么}

**延伸问题**：
- {如果想进一步了解，可能会问的下一个问题}
- {另一个相关问题}

**置信度**：{高 / 中 / 低}
{如果是中/低，加：⚠️ 部分内容为AI推断，建议核实}

---
```

## 实际示例

```markdown
---
**Q01** [ARCH] 项目的模块是如何划分的？核心依赖关系是什么？

**答案**：
项目采用按业务功能划分模块的方式，核心模块包括 AuthModule（认证）、UserModule（用户管理）、PostModule（文章管理）。AppModule 作为根模块导入所有功能模块。AuthModule 依赖 JwtModule 和 PassportModule 实现 JWT 认证；UserModule 依赖 TypeOrmModule 进行用户数据持久化。

**关键代码位置**：
- `src/app.module.ts:1-20` — 根模块导入所有子模块
- `src/auth/auth.module.ts:10-25` — AuthModule 依赖 JwtModule 和 PassportModule

**延伸问题**：
- 如何添加一个新的业务模块？
- 模块之间的循环依赖如何处理？

**置信度**：高

---
```
