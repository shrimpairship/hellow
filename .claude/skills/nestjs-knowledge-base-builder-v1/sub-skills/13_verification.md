# 子Skill 13: 验证与修正

> **职责**: 所有12+1个文档生成完毕后，执行全面验证，输出修正清单。
> **输入**: 12+1个输出文档 + `_analysis/` 中间产物 + 源码快照
> **输出**: 修正操作（直接修复文档中的问题） + 验证报告

---

## 必须遵守的共享规则

开始前先读取:
- `shared/quality_checklist.md` — 完整的质量检查清单
- `shared/iron_rules.md` — 铁律规则

---

## 验证流程

### 阶段 1: 完整性检查

逐项检查 `quality_checklist.md` 完整性检查项（A-E组）：

**A. 文档数量**
- [ ] 检查 `00_阅读指南.md` 是否存在
- [ ] 检查 `01_项目介绍.md` 是否存在
- [ ] 检查 `02_模块架构.md` 是否存在
- [ ] 检查 `03_路由与控制器.md` 是否存在
- [ ] 检查 `04_服务与业务逻辑.md` 是否存在
- [ ] 检查 `05_数据模型与DTO.md` 是否存在
- [ ] 检查 `06_API接口文档.md` 是否存在
- [ ] 检查 `07_数据库与数据流.md` 是否存在
- [ ] 检查 `08_配置与环境.md` 是否存在
- [ ] 检查 `09_项目结构总览.md` 是否存在
- [ ] 检查 `10_核心函数语义.md` 是否存在
- [ ] 检查 `11_常见问题清单.md` 是否存在
- [ ] 检查 `SUMMARY.md` 是否存在

### 阶段 2: 内容检查

**B. 模块覆盖**
- [ ] 遍历 `_analysis/module_analysis.md` 中的模块列表，确认每个模块都在 `02_模块架构.md` 中有对应章节
- [ ] 检查每个模块的 imports/exports/controllers/providers 是否已列出

**C. 路由覆盖**
- [ ] 遍历 `_context/route-graph.json` 或 `_analysis/route_analysis.md` 中的路由，确认每个路由都在 `03_路由与控制器.md` 中有记录

**E. 问题分级**
- [ ] 检查发现的问题是否都有 P0/P1/P2/P3 标签
- [ ] 检查每个问题是否有文件名+行号

### 阶段 3: 正确性回查

**F. 路由路径一致性**
- [ ] 随机抽取3个路由，验证 Controller prefix + method decorator 拼接结果与实际一致

**G. 依赖注入一致性**
- [ ] 随机抽取2个 Service，验证 constructor 注入与 Module providers 声明一致

**H. 数据模型一致性**
- [ ] 随机抽取1个 Entity，验证字段与 DTO 字段一致

### 阶段 4: 反偷懒检查（铁律10）

**I1. 禁止泛指省略**
- [ ] 在所有文档中搜索"以此类推"、"等"、"类似地" -> 如有直接修正

**I2. 禁止空壳章节**
- [ ] 检查每个章节是否有实质内容（Mermaid图、表格行数≥2、列表项≥3、连续段落≥3行）

**I3. 最低内容标准**
- [ ] `02_模块架构.md`：模块章节数 ≥ 实际 Module 数
- [ ] `03_路由与控制器.md`：路由表行数 ≥ 路由总数
- [ ] `06_API接口文档.md`：API 条目数 ≥ 路由总数
- [ ] `11_常见问题清单.md`：Q&A 数量 = 20

### 阶段 5: 输出验证报告

```markdown
# 验证报告

**项目**: [项目名称]
**验证时间**: [时间]
**验证结果**: ✅ 通过 / ⚠️ 部分通过 / ❌ 未通过

---

## 检查结果汇总

| 检查项 | 结果 | 问题数 |
|--------|------|--------|
| A. 文档数量 | ✅ | 0 |
| B. 模块覆盖 | ✅ | 0 |
| C. 路由覆盖 | ⚠️ | 2 |
| ... | ... | ... |

## 已修正的问题

1. [文件名] — [问题描述] → [修正方式]

## 未修正的问题

1. [文件名] — [问题描述] — [原因]

## 建议

- [改进建议]
```

---

## 输出要求

- 发现问题时，先尝试自动修正，修正不了才列出
- 修正操作必须记录"修改前 → 修改后"
- 验证报告必须输出到知识库根目录（与文档同级）
