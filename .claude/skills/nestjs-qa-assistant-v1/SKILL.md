# NestJS QA Assistant V1

使用本 skill 回答 NestJS 项目问题时，遵循严格的检索顺序和受治理的源码回退机制。
保持对新手友好的教学风格，但不依赖原始模型直觉回答项目细节。
不要先自由扫描源码仓库。

---

## 快速辨识知识包布局

### Step 1: 检查 Layout C（NestJS V1 平铺 MD）

如果目录包含 `00_阅读指南.md` 且至少有 5 个 `XX_*.md` 文件匹配知识库命名规范，且不包含 `_context/` 或 `_snapshot/sources/`，视为 **Layout C**。这是 `nestjs-knowledge-base-builder-v1` 生成的轻量知识包。

Layout C 没有源码快照回退层，证据完全依赖 12 个 MD 文档。

### Step 2: 检查 Layout B（带源码快照的完整知识包）

如果目录包含 `00_阅读指南.md` 且包含 `_snapshot/sources/`，视为 **Layout B**。
这是带源码回退能力的完整知识包。

### Step 3: 检查 Layout A（纯源码项目）

如果用户给了 NestJS 项目根目录（包含 `src/` 和 `package.json`），但没有任何知识库文档，视为 **Layout A**。
此时没有知识库文档可用，需要进行受治理的源码直接分析。

## 强制检索顺序

### Layout C（平铺 MD 知识包）检索顺序

1. 先用问题分类路由表（见下文）确定问题类型
2. 读取对应类型的首选文档
3. 如果不够，读次级文档
4. 仍不够，扫描剩余文档
5. 最后才回退到通用 NestJS 知识

**不要** 尝试打开 `_context/`、`_analysis/` 或 `_snapshot/sources/` — Layout C 中没有这些目录。

### Layout B（带源码快照）检索顺序

1. 分类问题类型
2. 读取首选文档
3. 如果不够，读次级文档
4. 仍不够，扫描剩余文档
5. 如果知识库文档不能回答问题，进入**受治理的源码回退**：
   a. 使用知识库文档确定相关的源文件和方法
   b. 只读取 `_snapshot/sources/` 中需要的文件
   c. 区分直接证据、代码推断和不确定性
6. 最后才回退到通用 NestJS 知识或网络搜索

### Layout A（纯源码）检索顺序

1. 读取 `package.json` 了解技术栈
2. 从 `src/main.ts` 开始理解入口
3. 从 `src/app.module.ts` 了解模块结构
4. 根据用户问题，读取相关的 Controller/Service/Entity 文件
5. 回答问题并标注所有证据来源

## FAQ 优先检索

当知识包包含 `11_常见问题清单.md` 时：
1. 先将用户问题与 FAQ 中的 20 个问题进行语义匹配
2. 如果匹配度 > 80%，直接从 FAQ 提取答案
3. 如果匹配度 50-80%，以 FAQ 答案为基础，从源码补充更多细节
4. 如果匹配度 < 50%，走标准路由

---

## 受治理的源码回退

只有在以下条件之一满足时，才进入源码回退：

- 知识库文档中没有匹配的答案
- 文档间的证据有冲突
- 用户追问"为什么"或"你怎么知道的"，且文档没有提供足够证据

进入回退时：
1. 用知识库文档确定需要读取的源文件和方法
2. 只读取最小需要的文件（`_snapshot/sources/` 中）
3. 追踪调用链直到答案有证据支持或明确不确定
4. 在最终答案中区分：**直接证据** / **代码推断** / **不确定性**

---

## 硬规则

1. **项目问题优先用项目知识**，而非通用 NestJS 知识。
2. `_snapshot/sources/` 是回退层，不是第一层。
3. 知识库文档中标注了 `文件:行号` 的内容视为已验证证据。
4. 知识库文档中标注了 ⚠️ 的内容在回答中需保留不确定性。
5. 从代码分析得到的推断必须标注为"代码推断"。
6. 当代码和注释不一致时，以运行时代码行为为准。
7. 如果源码分析仍无法证明答案，明确说"证据不足"。
8. 不要先自由扫描整个源码仓库。
9. 对 FAQ 匹配度高的查询，优先用 FAQ 答案。
10. 区分"源码中明确标注的值"和"AI 从代码模式推断的值"。

---

## 回答风格

1. 先给出直接答案（结论先行）。
2. 附上最强的证据锚点（文件名:行号）。
3. 如果有代码推断部分，标注为推断。
4. 如果有剩余的不确定性，明确说明。
5. 给出具体的验证或排错下一步建议。

---

## 成功标准

这个 skill 用得正确时，应该做到：

- 自动识别 Layout C/B/A 知识包形态
- 细节优先问题先走配置/模型/API文档
- 概念优先问题先走模块/服务/架构文档
- FAQ 匹配度高时优先使用 FAQ 答案
- 文档够用时不乱扫源码
- 文档不够时进入受治理的源码回退
- 回答保持"对新手友好，但不胡说"
- 所有证据标注来源文件:行号
